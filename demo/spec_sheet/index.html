The instrument's spec sheet

The two demo pages show what the tool-choice SAEs can do. This page measures where they stop working — using only data the project already had: the 95,386 stored decision-token vectors, the pairs parquet, and retrained dictionaries that cost ~18 seconds each. Splits are leak-free at the level of connected components of the prompt-pair graph; every held-out number below comes from prompts neither the dictionary nor the probe ever saw.

What was trained and held out

Four dictionaries per layer, the shipped six-layer configuration exactly (d_sae 10752, target L0 75, auto-calibrated thresholds), from the existing activation shards.

Cross-scenario reach — layer

Explained variance of each dictionary's reconstruction on held-out prompts of each scenario. PCA-75 is the dense linear reference fit on the same training split; “aligned” re-centers/rescales the eval set to the dictionary's training statistics before encoding (the norm-matched control).
The “shipped” rows saw every eval vector during training — they are shown for reference, not as held-out numbers. Cross-domain L0 is the same dictionary firing on inputs it was never calibrated for: the instrument does not fail silently out of domain, it fires an order of magnitude more features.

Is a “feature” a stable object? retraining-seed test

The same data, the same configuration, a different random seed (joint vs joint_seed123) — then match every frequently-firing feature to its best counterpart, by decoder direction and by co-activation on held-out prompts.
Comparisons without a firing-rate cut are meaningless here: dead and ultra-rare rows sit at their initialization, and same-seed runs share initialization — uncut same-seed matching reaches ~0.9 decoder cosine on that artifact alone. Consequence for the demos: feature indices and directions are properties of one trained dictionary, not of the model; labels can only be carried across dictionaries functionally, and interventions must be re-derived per dictionary.

Do the features carry the decision signal?

Predict a held-out prompt's tool label (the generator's intent) from three representations, same split for all: bag-of-words on the request text, the raw 2688-d residual, and the fair joint SAE's features.
Labels come from the pair generator, not from the model's own choice — the population census below measures the model's actual decisions. The SAE and the probe never saw the test prompts.

Do feature labels name the pair's signal?

For held-out pairs: do the top anchor-side / contrast-side features' labels share a content word with the matching clause of the pair's distinguishing_signal annotation, versus the same score with signals shuffled across pairs?

The population, not the showcase

“Agreement” is against the pair generator's intended tool — intent, not ground truth; the model disagrees with the generator on roughly half of all sides even though its own choices are decisive. The seen/unseen split refers to whether the pair's prompts entered SAE training (the readout itself never involves the SAE) — and the unseen stratum concentrates in low-flip contrast types, so its flip rate is not directly comparable to the seen stratum's.

Where interventions bite — layer by layer

The tool_selection demo's causal battery (family ablations, cross-patching, mass-matched random controls) run at every trained depth on the same 7 rule-selected pairs. HF backend with fused kernels; vLLM residual parity shown on the demo page.

Does the causal result depend on the dictionary?

The same battery at layer 43, with dictionaries the capture never used — families re-derived by encoding the captured vLLM residuals with each dictionary. The new dictionaries are unlabeled, so family granularity differs from the shipped run: the comparison is qualitative (does the battery still move the decision?), not effect-size-matched.

Standing caveats

  • These SAEs are decision-token, two-scenario instruments: trained only on the hidden state after “I'll use the”, only on home_repair and tool_selection prompts.
  • Pairs, feature labels, and signal annotations come from the same LLM family — “meaning” claims partially inherit the generator's notion of meaning.
  • Observational numbers come from the modified-vLLM backend; interventions run on HF with fused Mamba kernels (residual cosine ≥ 0.99 vs vLLM).
  • All-families ablation arms are compared against per-family mass-matched controls, which are smaller sets — the per-family rows are the like-for-like comparison.
